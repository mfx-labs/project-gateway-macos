# Project Gateway for macOS v0.2.1 (patch)

v0.2.1 is a patch release that ships the accepted **operator-v2 persistence
correction** on top of the v0.2.0 codebase. The pre-existing annotated
`v0.2.0` release tag is treated as immutable historical identity and is left
untouched; corrected content is released here as v0.2.1.

## Highlights

- **Operator-controlled persistence v2:** the operator runtime now emits
  trusted workspace configuration `configurationVersion '2'` with a
  deterministic workspace-local artifact location (`<workspace>/artifacts`).
  `pgw add` provisions the artifact directory and bootstraps a version-2
  store, and `pgw start` / `pgw doctor` derive the same version-2
  configuration identity.
- Previously, the operator emitted version-1 configuration with no artifact
  location, so `persist-artifact` was rejected by the version-2
  destination-containment gate (TAD-002). That live failure is now closed.
- Proposal persistence remains **proposal-only, create-only,
  destination-derived, containment-bound, and independently revalidated**; it
  grants no approval / issuance / grant / activation / execution authority and
  creates no trusted lifecycle record.

## Correctness / Security

- Corrected operator configuration identity matches the accepted
  controlled-write protocol; artifact location is deterministic and a strict
  descendant of the workspace root.
- TAD-002 still rejects any direct version-1 controlled write.
- TAD-039 existing-target denial unchanged (create-only, no overwrite).
- Independent artifact validation, destination derivation, containment, and
  no caller-supplied path are unchanged.
- `verifyStoreInstance` strictness and StoreMetadata immutability unchanged.

## Legacy state policy

`configurationVersion '1'` is unsupported pre-release/development state for
this product lifecycle. No in-place v1 → v2 migration is provided. The
supported path is clean uninstall/reset and fresh re-provisioning. No
migration subsystem exists and none is claimed.
